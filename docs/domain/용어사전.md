# 용어사전

프로젝트에서 쓰는 도메인 용어와, 그 용어가 코드에서 갖는 이름을 고정한다.
문서·대화·코드에서 **같은 것을 같은 말로** 부르기 위한 기준이다.

## 문서를 쓰는 규칙

- **바운디드 컨텍스트마다 섹션이 나뉜다.** 용어의 의미는 컨텍스트 안에서만 일관된다.
  컨텍스트를 밝히지 않은 용어는 이 문서에 없다.
- **한 컨텍스트 안에서 용어는 하나의 뜻만 갖는다.** 뜻이 둘이면 용어를 쪼개거나 컨텍스트를 쪼갠다.
- **동명이의어에 접두사를 붙이지 않는다.** `커뮤니티회원`·`인증사용자` 같은 이름을 만들지 않는다.
  아무도 대화에서 그렇게 부르지 않기 때문에 코드가 실제 언어와 어긋난다.
  대신 컨텍스트를 나누고 아래 [컨텍스트 간 대응](#컨텍스트-간-대응)에서 잇는다.
- **기획 용어를 그대로 쓴다.** 화면과 정책 문서가 "원픽"이라 부르면 코드도 `pick`이다.
  번역하거나 일반화하지 않는다.

## auth 컨텍스트

소셜 로그인으로 신원을 확인하고 권한을 부여한다.

| 용어 | 코드 식별자 | 종류 | 정의 |
|---|---|---|---|
| 사용자 | `User` | 명사(애그리거트 루트) | 소셜 신원으로 시스템에 로그인하는 주체. → [컨텍스트 간 대응](#컨텍스트-간-대응) 참고 |
| 소셜 제공자 | `SocialProvider` | 명사 | 신원을 보증하는 외부 서비스. 카카오·애플 |
| 상태 | `State.ACTIVE` / `State.INACTIVE` | 상태 | 로그인 가능 여부. 탈퇴하면 비활성이 된다 |
| 탈퇴 | `withdraw` | 동사 | 사용자가 서비스 이용을 끝내는 사건. 데이터를 지우지 않고 비활성으로 표시한다 |

## community 컨텍스트

게시글을 올리고 투표하고 댓글을 단다. 서비스의 핵심이다.

| 용어 | 코드 식별자 | 종류 | 정의 |
|---|---|---|---|
| 게시글 | `Post` | 명사(애그리거트 루트) | 의견을 묻기 위해 올리는 글 한 건. 유형에 따라 딸린 것이 달라진다 |
| 게시글 유형 | `PostType` | 상태 | `AGREE`(찬반) · `A_B` · `GENERAL`(일반) 셋 중 하나 |
| 찬반 PICK | `PostType.AGREE` | 상태 | 상품 하나를 놓고 살지 말지를 묻는 게시글 |
| A/B PICK | `PostType.A_B` | 상태 | 상품 둘 중 어느 쪽인지를 묻는 게시글 |
| 일반 게시글 | `PostType.GENERAL` | 상태 | 투표 없이 제목과 설명만 있는 게시글 |
| 카테고리 | `PostCategory` | 상태 | 게시글 분류. 패션·잡화 / 전자제품 / 화장품·뷰티 / 생활용품 / 기타 |
| 상품 | `PostProduct` | 명사 | 게시글이 의견을 묻는 대상. 찬반은 한 점, A/B는 두 점 |
| 선택지 | `PostOption` | 명사 | 투표에서 고를 수 있는 항목. **게시글당 정확히 둘이거나 없다** |
| 투표 | `Vote` | 명사 | 선택지 하나를 고른 사건. **한 게시글에 한 사람은 한 번** |
| 댓글 | `Comment` | 명사 | 게시글에 남기는 의견 |
| 원픽 | `pick()` / `OnePick` | 동사 · 명사 | 사용자가 게시글의 댓글 하나를 고르는 **행위**. 댓글 작성자 본인을 제외한 누구나 할 수 있고 사용자마다 게시글당 한 번이다(`UNIQUE(user_id, post_id)`). **자기 댓글은 고를 수 없다**(R-07). 동사는 `Comment.pick(pickerId)`, 그 결과가 값 객체 `OnePick` |
| 원픽 수 | `pickCount` | 명사 | 한 댓글이 받은 원픽 **개수**. 게시글 단위 집계는 `comment_pick.post_id`로 조인 없이 센다 |
| 작성자 | `authorId` | 역할 | 게시글이나 댓글을 쓴 사람. → [컨텍스트 간 대응](#컨텍스트-간-대응) 참고 |
| 게스트 | — | 역할 | 로그인하지 않고 둘러보는 사람. **서버에 기록을 남기지 않는다** |
| 댓글 인원 | `commenterCount` | 명사 | 그 게시글에 댓글을 단 **사람 수**. 댓글 건수와 다르다 |
| 댓글 건수 | `commentCount` | 명사 | 그 게시글의 댓글 **개수**. 화면 표시용이며 인기순 계산에 쓰지 않는다 |
| 인기 점수 | `popularityScore` | 명사 | 투표 인원과 댓글 인원의 합. 인기순 정렬 기준 |

### 게시글 유형을 셋으로 부르되 셋으로 나누지 않는 이유

찬반과 A/B는 대화에서 다른 이름으로 불리므로 용어를 각각 둔다.
그러나 **둘 다 "선택지 둘 중 하나를 고르는 일"이라는 점은 같다.**
이 사실이 모델에서 `Vote`를 하나로 유지하는 근거다.
자세한 것은 [도메인 모델.md](./도메인%20모델.md)와 [ERD 초안](../erd/ERD-초안.md) 8.1 참고.

## reward 컨텍스트

활동에 대가를 주고 등급과 뱃지로 표시한다.

| 용어 | 코드 식별자 | 종류 | 정의 |
|---|---|---|---|
| 포인트 | `point` | 명사 | 활동으로 쌓이는 점수. 등급 승급 조건이자 랭킹 정렬 기준 |
| 포인트 이력 | `PointHistory` | 명사(애그리거트 루트) | 포인트가 언제 왜 얼마나 움직였는지 남기는 원장. **잔액의 근거** |
| 적립 사유 | `PointReason.PICKED` / `PICKING` | 상태 | 내 댓글이 원픽됨(+10P) / 내가 원픽함(+5P) |
| 등급 | `Grade` | 명사 | LV.1~LV.5. **누적 포인트와 누적 투표 횟수를 함께** 충족해야 오른다 |
| 뱃지 | `Badge` | 명사 | 투표 실적으로 얻는 표식. 누적·일일·연속 세 유형이 있다 |
| 획득 조건 | `BadgeConditionType` | 상태 | `TOTAL_VOTE`(누적) · `DAILY_VOTE`(하루) · `STREAK_VOTE`(연속) |
| 일별 활동 | `UserDailyActivity` | 명사 | 날짜별 투표 수. 일일·연속 뱃지를 판정하는 근거 |
| 랭킹 | — | 명사 | 포인트 순 정렬. 동점이면 가입이 빠른 쪽이 앞선다 |

## 컨텍스트 간 대응

같은 사람을 컨텍스트마다 다르게 부른다. 접두사로 구분하지 않는다.

| auth | community | reward | 관계 |
|---|---|---|---|
| 사용자 `User` — 로그인하는 주체 | 작성자·투표자 `authorId`, `voterId` — 글을 쓰고 투표하는 역할 | 적립 대상 `userId` — 포인트가 쌓이는 대상 | **같은 사람이다.** 세 컨텍스트 모두 `User`의 식별자를 참조한다 |

템플릿에서 물려받은 용어사전은 `member`·`account`를 기각하고 `User`를 쓰기로 하면서
**"회원 개념이 생기면 그때 별도 용어로 추가한다"**고 적어 두었다.

Pickple은 그 시점에 해당한다. 그러나 **새 용어를 만들지 않는다.**
커뮤니티에서 필요한 것은 "회원 자격"이 아니라 **글을 쓰고 투표하는 역할**이고,
그 역할은 이미 `User`가 맡을 수 있기 때문이다.
`User`에 닉네임·프로필·포인트가 붙는 것은 새 개념의 등장이 아니라 기존 개념의 성장이다.

→ 이 판단의 스키마 측 결과는 [ERD 초안](../erd/ERD-초안.md) 1.4 참고.
`member` 테이블을 만들지 않고 `users`를 확장한다.

## 기각한 표현

같은 것을 부르는 다른 후보와, 그것을 쓰지 않기로 한 이유.

| 쓰지 않는 표현 | 대신 쓰는 표현 | 이유 |
|---|---|---|
| `member`, `account` | `User` | 물려받은 규약을 유지한다. 위 [컨텍스트 간 대응](#컨텍스트-간-대응) 참고 |
| `status` | `state` | 이 도메인의 상태는 값이 정해진 전이 대상이지 진행 경과가 아니다 |
| `bestComment`, `adoptedComment`, `pickedComment` | `OnePick` / `Comment.pick()` | 기획과 화면이 "원픽"이라 부른다. 번역하면 대화와 코드가 갈라진다. `pickedComment`는 작성자가 하나를 채택하던 시절의 이름이라 함께 버린다 |
| `CommentPick`(엔티티로) | `OnePick`(값 객체) + `Comment.pick()` | 원픽은 **행위**다. 테이블 이름을 그대로 클래스로 옮기면 동사가 명사로 납작해진다 |
| `like`, `recommend` | `vote` | 투표는 찬성 표시가 아니라 **둘 중 하나를 고르는 일**이다. 좋아요와 섞이면 안 된다 |
| `poll`, `survey` | `post` | 투표는 게시글의 일부이지 별도 개체가 아니다. 일반 게시글에는 투표가 없다 |
| `choice`, `candidate` | `option` (`PostOption`) | 선택지는 화면 용어와 맞춘다 |
| `score` | `point` | 정책 문서가 포인트(P)로 쓴다 |
| `level` 단독 | `grade` (등급) / `Grade.level` | 등급은 개념, 레벨은 그 등급의 번호다. 둘을 섞으면 LV.3이 등급인지 숫자인지 흐려진다 |
| `deleteYn`, `isDeleted` | `deletedAt` | 삭제는 사건이므로 시점을 남긴다. 불린은 언제 지웠는지를 잃는다 |
| `count` 단독 | `voteCount`, `commentCount` | 무엇을 센 값인지 이름에 남긴다 |
| `commentCount`로 인기 점수 계산 | `commenterCount` | 정책은 댓글 **인원 수**다. 건수를 쓰면 혼자 순위를 올릴 수 있다 |

## 아직 정하지 않은 것

| 용어 후보 | 상황 | 결정 시점 |
|---|---|---|
| 신고 / 차단 | 화면에 버튼과 모달은 있으나 **동작하지 않는다**(기능 X). 용어를 고정하면 쓰이지 않는 이름이 남는다 | 기능이 실제로 만들어질 때 |
| 게스트 식별자 | 게스트 투표 3회 제한을 서버에 남길지 미정. 지금은 클라이언트가 센다 | 서버 저장이 필요해질 때 |
| 강등 | 포인트 회수가 생기면 등급이 내려갈 수 있다. 지금은 승급만 있다 | 회수 정책이 생길 때 |
