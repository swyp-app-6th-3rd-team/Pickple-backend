# requirement — 기획 원문

기획이 준 산출물의 **원문**이다. 이 폴더의 파일은 **수정하지 않는다.**
해석·판단·설계는 `docs/domain/`·`docs/adr/`·`docs/prd/` 가 맡는다.

## 정본 위계

대조 순서다. 아래가 위를 이기지 못한다.

1. **화면설계서** (Figma) — 화면 동작의 최종 정본
2. **정책 요약표** — 수치·제약(포인트·등급·뱃지·입력 규칙)의 정본
3. **기능명세서** — 기능 흐름과 예외 처리
4. 그 외 해석·전달 내용

명세가 서로 어긋나면 위 순서로 판정하고, 판정 결과를 이슈나 ADR 에 남긴다.
빈칸이면 지어내지 말고 이슈에 `needs-spec` 라벨을 단다.

## 파일

| 파일 | 상태 | 비고 |
|---|---|---|
| `기능명세서 v0.3.pdf` | **현행 정본** | 31p |
| `기능명세서 v0.2.pdf` | 이력 | 33p. 기존 이슈 다수가 이 버전을 인용한다 |
| `기능명세서 v0.1.pdf` | 이력 | 32p |
| `정책 요약표.pdf` | **현행 정본** | 3p. 포인트·등급·뱃지·닉네임·게시글 입력·정렬 |

`*.txt` 는 각 PDF 의 추출 텍스트다. `git diff` 와 `grep` 을 쓰려고 둔 **파생물이며 정본이 아니다.**
표 구조가 컬럼 순서로 펼쳐지므로 문장이 끊겨 보일 수 있다 — 판단이 걸리면 PDF 를 직접 본다.

재생성:

```bash
python3 -c "
import fitz, glob, os
for pdf in sorted(glob.glob('docs/requirement/*.pdf')):
    d = fitz.open(pdf)
    with open(pdf[:-4] + '.txt', 'w') as fh:
        fh.write(f'# {os.path.basename(pdf)} 추출 텍스트\n')
        fh.write('# 원문은 같은 폴더의 PDF다. 이 파일은 git diff·grep 을 위한 파생물이며 정본이 아니다.\n')
        fh.write(f'# 생성: pymupdf get_text(), 총 {d.page_count}페이지\n')
        for i, p in enumerate(d):
            fh.write(f'\n===== p{i+1} =====\n')
            fh.write(p.get_text('text'))
"
```

### 게스트 제약 — 계수는 사실이 아니다

'게스트' 언급이 20 → 27 건으로 늘었지만, **늘어난 7 건 중 6 건은 신규가 아니다.**
v0.3 에서 페이지 한 장이 빠지면서 같은 문장이 페이지 경계에서 다르게 잘렸을 뿐이다
(예: "투표 3번까지 허용" 은 v0.2 에도 있다).

실제 신규는 §6.4 **1 건**이다. 다음 버전을 대조할 때도 계수 증감만 보고 판단하지 말고
문장 단위로 확인한다.

### 확인한 것 — 원픽 규칙은 유효하다

`docs/domain/도메인 모델.md` 의 R-05·R-06 이 인용하는 문장
`원픽 취소 불가(한 게시글에 하나의 원픽만 가능)` 는 v0.3 에도 그대로 있다.
'원픽' 언급 수도 양쪽 19 건으로 같다. 페이지 위치만 옮겨졌으므로
[ADR-0018](../adr/0018-onepick-as-behavior.md)·[ADR-0020](../adr/0020-onepick-uniqueness-scope.md) 은
내용상 유효하며 `Superseded` 대상이 아니다.
