# requirement — 기획 원문

기획이 준 산출물의 **원문**이다. 이 폴더의 파일은 **수정하지 않는다.**
해석·판단·설계는 `docs/domain/`·`docs/adr/`·`docs/prd/` 가 맡는다.

## 정본 위계

대조 순서다. 아래가 위를 이기지 못한다.

1. **화면설계서** (Figma) — 화면 동작의 최종 정본
2. **정책 요약표** — 수치·제약(포인트·등급·뱃지·입력 규칙)의 정본
3. **기능명세서** — 기능 흐름과 예외 처리
4. 그 외 해석·전달 내용

명세가 서로 어긋나면 위 순서로 판정하고, 판정 결과를 이슈나 ADR 에 남긴다.
빈칸이면 지어내지 말고 이슈에 `needs-spec` 라벨을 단다.

## 파일

| 파일 | 상태 | 비고 |
|---|---|---|
| `기능명세서 v0.4.pdf` | **현행 정본** | 34p |
| `기능명세서 v0.3.pdf` | 이력 | 31p |
| `기능명세서 v0.2.pdf` | 이력 | 33p. 기존 이슈 다수가 이 버전을 인용한다 |
| `기능명세서 v0.1.pdf` | 이력 | 32p |
| `정책 요약표.pdf` | **현행 정본** | 3p. 포인트·등급·뱃지·닉네임·게시글 입력·정렬 |

`*.md` 는 각 PDF 를 표 구조에 맞춰 변환한 것이다. `git diff` 와 `grep` 을 쓰려고 둔
**파생물이며 정본이 아니다.**

원문 PDF(Notion 내보내기)는 표 셀을 **2~3자 단위로 하드랩**해 저장한다.
그래서 그냥 텍스트를 뽑으면 `기\n능그\n룹` 처럼 글자가 흩어진다.
`extract.py` 는 컬럼 그리드로 셀을 다시 묶고, 문서 순서대로 이어붙여 랩을 제거한 뒤
불릿(`•` → `-`)·라벨(`[기본 동작]`·`<조회 데이터>`)·`상황:`/`조치:` 구조를 복원한다.

**줄바꿈 위치는 원문과 다르다.** 인용할 때는 PDF 를 본다.

재생성:

```bash
python3 docs/requirement/extract.py   # docs/requirement/ 에서 실행
```

## v0.3 → v0.4 변경

### 계수부터

쪽수가 31 → 34 로 늘어 **쪽 단위로 비교하면 28쪽이 달라 보인다.** 실제로는 앞에 3쪽이
끼어들어 뒤가 통째로 밀린 것이다. 글자 단위로 정규화해 비교하면 **12,205자 중 932자 증가**이고,
그중 상당수가 표 머리글 반복(`기능그룹주요기능트리거…`)과 쪽 번호다.

`git diff` 로 `*.md` 를 볼 때도 같은 착시가 생긴다. **변경 규모를 쪽수나 diff 줄 수로 세지 않는다.**

**기존 번호가 밀리지 않았다.** v0.2 → v0.3 때 `§5.3` 하나가 의미를 바꿨던 것과 달리,

이슈를 만들지 않았다.

### 반영되지 않은 것 — 게시글 수정 범위

기획 담당자가 2026-09-05 구두로 **"수정할 시에는 카테고리, 주제나 제목, 설명만 수정할 수 있도록"**
확정하고 "기획문서 바꿔놓겠습니다" 라고 했으나, **v0.4 에 들어오지 않았다.**
§6.1 `[더보기]` 분기 처리는 v0.2·v0.3 과 글자 그대로 같고, 문서 전체에서 "수정 가능" 이라는
표현은 댓글 수정 한 건뿐이다.

→ #32 에 기록했고 그 이슈는 **열어 둔다.** 갱신본이 나올 때까지 구두 확인이 잠정 근거다.

### 게스트 제약 — 계수는 사실이 아니다

'게스트' 언급이 20 → 27 건으로 늘었지만, **늘어난 7 건 중 6 건은 신규가 아니다.**
v0.3 에서 페이지 한 장이 빠지면서 같은 문장이 페이지 경계에서 다르게 잘렸을 뿐이다
(예: "투표 3번까지 허용" 은 v0.2 에도 있다).

실제 신규는 §6.4 **1 건**이다. 다음 버전을 대조할 때도 계수 증감만 보고 판단하지 말고
문장 단위로 확인한다.

### 확인한 것 — 원픽 규칙은 유효하다

`docs/domain/도메인 모델.md` 의 R-05·R-06 이 인용하는 문장
`원픽 취소 불가(한 게시글에 하나의 원픽만 가능)` 는 v0.3 에도 그대로 있다.
'원픽' 언급 수도 양쪽 19 건으로 같다. 페이지 위치만 옮겨졌으므로
[ADR-0018](../adr/0018-onepick-as-behavior.md)·[ADR-0020](../adr/0020-onepick-uniqueness-scope.md) 은
내용상 유효하며 `Superseded` 대상이 아니다.
