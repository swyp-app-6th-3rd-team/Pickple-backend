# PRD-016 — 등급 도메인과 승급 판정

**이슈**: #25 · **ADR**: [0030](../adr/0030-grade-derives-from-ledger-and-only-rises.md) · **작성**: 2026-09-04

## 무엇을 왜

등급(Grade) 도메인이 없다. 규칙만 문서에 있다 — 정책 요약표 §2 가 임계값을 정하고
도메인 모델이 R-15·R-16 으로 옮겨 적었지만 **코드도 테이블도 없다.**

마이페이지의 "나의 등급" 화면(기능명세 §11.1·§11.2)이 이것 없이는 열리지 않는다.
포인트 지급(#24)과 투표(#21)가 이미 머지되어 **판정 입력값이 쌓이기 시작했는데
그것을 등급으로 읽어주는 쪽이 비어 있다.**

### 착수 전 확인한 것 — 입력값이 "이미 있다" 는 말은 절반만 맞다

| 컬럼 | V3 선언 | 실제 상태 |
|---|---|---|
| `users.point` | "point_history 합계" | 랭킹 배치(5분 주기)만 채운다 → 최대 5분 낡음 |
| `users.vote_count` | "vote 건수" | **쓰는 코드 0건**(전수 grep) → 읽으면 전원 0 |

`users.vote_count` 를 읽었다면 **아무도 승급하지 못하는데 테스트는 초록**인 상태가 됐다.
ADR-0028 이 `users.point` 에서 이미 짚었던 함정과 같은 종류다.
→ 판정 입력값을 원장에서 읽기로 한 근거([ADR-0030](../adr/0030-grade-derives-from-ledger-and-only-rises.md) 결정 1).

### 제외 (의도적으로 미룸)

- **등급 일러스트 이미지 자체** — 명세의 조회 데이터에 "등급 일러스트" 가 있지만
  이미지 URL 은 화면설계서(Figma)가 정본이고 아직 확정 전이다.
  응답에는 등급 식별자(`level`·`name`)를 싣고 프론트가 매핑한다. 빈칸을 지어내지 않는다.
- **`users.vote_count` 채우기** — 아무도 읽지 않는 컬럼이라 지금 깨지는 것이 없다.
  뱃지(#27)가 같은 입력값을 쓰므로 그쪽과 함께 정리할 자리다(ADR-0030).
- **승급 알림·실시간 푸시** — §7.3 의 "실시간" 은 조회 시점 최신값을 뜻하는 것으로 읽었다.
  서버 푸시는 이 이슈의 API 계약에 없다.
- **강등** — 회수 정책이 없다(R-16). 생기면 ADR-0030 을 재검토한다.

## 완료 판정

이슈 #25 의 완료 판정 표를 그대로 옮기고, 검증 수단을 명시한다.

| # | 판정 | 검증 방법 | 근거 |
|---|---|---|---|
| 1 | 누적 200P · 투표 **19회** 에서 LV.2 로 오르지 않는다 | `GradeTest` 경계값 | R-15 AND |
| 2 | 누적 **199P** · 투표 20회 에서 LV.2 로 오르지 않는다 | `GradeTest` 경계값 | R-15 AND |
| 3 | 누적 200P · 투표 20회 에서 LV.2 로 오른다 | `GradeTest` 경계값 | 정책표 §2 |
| 4 | 포인트가 줄어도 등급이 내려가지 않는다 | `GradeServiceIT` — 승급 후 원장을 차감하고 재조회해 등급 유지 확인 | R-16 |
| 5 | 재투표가 승급 판정의 투표 횟수를 늘리지 않는다 | `JpaGradeStoreIT` — 같은 게시글에 선택 변경 후 횟수 동일 | R-22 |
| 6 | 저장된 포인트가 이력 합계와 일치한다 | `JpaGradeStoreIT` — `SUM(point_history)` 와 조회값 대조 | R-14 |
| 7 | LV.5 도달 후 다음 등급이 없고 달성률이 100% 다 | `GradeTest` — 최고 등급 경계 | 명세 §11.1 |
| 8 | 가입 직후(0P·0회) 등급이 LV.1, 달성률 0% 다 | `GradeServiceIT` | 정책표 §2 "가입 시 기본 부여" |

판정 1~3·7 은 순수 함수라 단위 테스트로 끝난다. 4~6·8 은 원장·스키마가 얽혀 통합 테스트다.

**대리지표 금지**: "빌드 green" · "테스트 통과" 자체는 완료 판정이 아니다.
위 8개 항목 각각이 어떤 테스트의 어떤 단언으로 확인됐는지 PR 본문에 적는다.

## 열린 질문

- **등급 일러스트의 정본** — 화면설계서 확정 후 응답에 URL 을 실을지, 프론트 매핑으로 둘지 재검토.
- **`GET /api/grades` 의 인증** — 이슈 표기는 "—" 다. 게스트에게 열려면 `SecurityConfig.PUBLIC_GET`
  추가가 필요하고 그 파일은 #26 도 건드린다. 이 PR 은 **인증 필요로 두고**(기본값)
  게스트 노출이 필요해지면 별도로 연다 — 마이페이지 하위 화면이라 게스트 진입 경로가 없다.
- **투표 행이 많은 사용자의 `COUNT(*)` 비용** — 측정하지 않았다(ADR-0030 열린 질문).
