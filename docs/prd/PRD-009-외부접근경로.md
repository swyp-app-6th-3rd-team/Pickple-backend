# PRD-009 — 운영 DB·SSH 외부 접근 경로

**이슈**: #50 · **ADR**: [0023](../adr/0023-external-db-ssh-access.md) · **작성**: 2026-09-02

## 무엇을 왜

로컬 DB 툴(DataGrip 등)과 SSH 클라이언트로 운영 EC2 에 **직접** 붙을 수 있게 한다.

현재는 SSM 터널을 매번 열어야 하고, MySQL 은 compose 내부 전용이라 호스트 포트 바인딩이
없어서 포트 포워딩만으로는 GUI 툴이 붙지 않는다. DB 를 보려면 SSM 셸 → `docker exec` →
CLI mysql 뿐이다. 이 마찰을 없앤다.

- **MySQL**: `54.116.14.198:13307` (compose `13307:3306`)
- **SSH**: `54.116.14.198:124`

두 포트 모두 **EIP `54.116.14.198` 하나**에 붙는다. MySQL 은 별도 서버가 아니라 같은 EC2 안의
컨테이너라 전용 엔드포인트가 없다. EIP 는 고정 주소이므로 인스턴스가 replace 돼도 접속 정보가 그대로다.

## 범위

**포함**
- `terraform/variables.tf` — `ssh_public_key`(필수), `ssh_port`, `mysql_allowed_cidr`, `mysql_host_port` 신규.
  `ssh_allowed_cidr` 는 기존 것 재사용
- `terraform/vpc.tf` — mysql 인그레스 신규, ssh 인그레스의 포트를 `var.ssh_port` 로 변수화, 상단 주석 갱신
- `terraform/ec2.tf` — `aws_key_pair.dev` 신규, `aws_instance.app` 에 `key_name` 추가
- `terraform/templates/user-data.sh.tftpl` — §4.5 SELinux `semanage` + `sshd_config` Port 변경
- `docker-compose-ec2.yml` — mysql `ports: ["13307:3306"]`
- 문서 — ADR-0023 신규, ADR-0012 §접속 경로 대체 포인터, `terraform/README.md`, tfvars 예시

**제외**
- SPEC 변경 — API·스키마 변경이 아니다
- 팀원별 SSH 키 배포 — 키 1개(`pickple-dev`)로 시작한다. 팀원이 붙어야 하면
  각자 공개키를 `authorized_keys` 에 추가하는 편이 낫다(키페어는 launch 시점 1개뿐)
- MySQL TLS(`require_secure_transport`) — 공개 개방이므로 필요하나 후속으로 분리
- SSM 제거 — 복구 경로로 그대로 둔다

## 수용한 위험

**1. DB 인터넷 노출 (`0.0.0.0/0`)**
`users`(소셜 로그인)와 `apple_provider_token`(암호화된 refresh token)이 담긴 DB 다.
EIP 는 고정 주소라 한 번 발견되면 계속 스캔 대상이 된다. 방어선은 계정 비밀번호 하나다.
→ 완화: remote root 차단, 앱 계정(`pickple`)으로만 접속, 비밀번호 강도 확인, 실패 로그인 관측법 문서화

**2. 인스턴스 replace (5~10분 중단)**
`key_name` 은 launch 시점에만 설정되므로 강제 교체가 일어난다.
→ `/data` 는 별도 EBS + `prevent_destroy`, attachment 에 `force_detach = true` → **데이터 보존**
→ EIP 는 `instance = aws_instance.app.id` 참조 → **IP·DNS 불변**
→ ⚠️ **인스턴스 ID 변경** → `vars.EC2_INSTANCE_ID` 갱신 필수

## 완료 판정

`terraform apply` 성공은 **대리지표이므로 판정에 쓰지 않는다.** 아래를 실제로 실행해 통과해야 한다.

- [ ] `curl -s -o /dev/null -w "%{http_code}" https://dev-api.pickple.app/actuator/health` → **200**
- [ ] `ssh -i ~/.ssh/pickple-dev.pem -p 124 ec2-user@54.116.14.198 "hostname"` → 응답
- [ ] `mysql -h 54.116.14.198 -P 13307 -u pickple -p pickple -e "SELECT version FROM flyway_schema_history ORDER BY installed_rank"` → **1, 3, 4**
- [ ] **데이터 보존** — replace 전후 `users` 행 수 동일, Caddy 인증서 재발급 안 됨(Let's Encrypt 발급 한도)
- [ ] SG 인바운드 = **80, 443, 124, 13307** (그 외 없음)
- [ ] `gh variable list` 의 `EC2_INSTANCE_ID` 가 새 인스턴스 ID
- [ ] remote root 차단 확인 — `mysql -h 54.116.14.198 -P 13307 -u root -p` 가 **거부**되어야 한다

## 열린 질문

1. **팀원 접속** — 키 1개로 시작한다. 공유가 필요하면 `authorized_keys` 방식으로 전환
2. **replace 실행 시각** — 5~10분 중단이 생기므로 팀 사용이 적은 시간대에 apply
3. **MySQL TLS** — 평문 전송이 남는다. 후속 이슈로 분리할지 판단 필요
4. **비용** — EIP·SG 변경은 추가 비용이 없다. PRD-008 의 2026-09-09 Cost Explorer 측정에 함께 확인
