# ADR-0049: 최초 약관은 열람 URL과 승인 전문을 함께 등록한다

- 상태: Accepted
- 날짜: 2026-09-11
- 관련 이슈: #147, #150
- 보완: ADR-0048의 버전별 약관 구조를 유지하고, 그 문서에서 후속으로 남긴 URL·정본 등록 결정을 확정한다.

## 맥락

ADR-0048과 V15는 약관 및 동의 이력 구조만 만들고 실제 약관 데이터는 비워 뒀다. 이후 이용약관과 개인정보처리방침이 최종 승인본으로 확정됐고, 두 문서의 시행 시각도 `2026-09-20 00:00:00` Asia/Seoul로 정해졌다.

기능명세서 v0.4 §1.6은 회원가입 화면에서 서비스 이용약관과 개인정보 수집 동의 문구를 누르면 각각의 Notion 링크로 내용을 표시하도록 요구한다. 한편 URL만 저장하면 같은 Notion 페이지가 수정되거나 사라졌을 때 사용자가 동의한 당시 문구를 재현할 수 없다.

개인정보처리방침 제1조는 회원가입 시 개인정보 수집·이용 내용을 제공하고 동의 체크를 받도록 하며, 이용약관 제5조는 이용약관과 개인정보처리방침 동의를 가입 신청의 조건으로 둔다.

## 결정

1. V15는 수정하지 않고 V16을 추가한다. V16은 `terms.content_url`을 비어 있지 않은 HTTPS 필수값으로 추가한다.
2. `TERMS_OF_SERVICE`와 `PRIVACY_POLICY`를 각각 한 행으로 등록한다. 두 행의 버전은 `2026-09-20`, 시행 시각은 `2026-09-20 00:00:00`, 필수 여부는 `TRUE`다.
3. `content_url`에는 앱이 열 Notion URL을, `content`에는 최종 승인 당시의 전체 Markdown 스냅샷을 저장한다. 공개된 행은 수정하지 않고 문서 개정 시 새 버전 행을 추가한다.
4. `created_at`은 문서 시행 시각이 아니라 V16이 해당 DB에 데이터를 등록한 시각이므로 `CURRENT_TIMESTAMP`를 사용한다.
5. 앱 버전/업데이트 안내는 약관 동의 대상이 아니므로 `terms`에 등록하지 않는다.
6. 이번 변경은 DB 등록까지다. 약관 조회, 동의 저장, 가입·서비스 이용 제한과 철회·탈퇴 보존 처리는 후속 API 및 정책 작업에서 연결한다.

## 결과

앱은 기능명세서에 적힌 URL로 문서를 열 수 있고, 백엔드는 각 동의가 가리키는 당시의 문구를 별도로 보존한다. Notion 문서가 바뀌어도 과거 버전의 증빙 내용은 DB 스냅샷으로 남는다.

V16은 V15 테이블이 계약대로 비어 있는 상태를 전제로 URL을 필수값으로 추가한 뒤 두 정본을 등록한다. V15를 수동으로 실행하고 계약 밖의 임시 약관 행을 넣은 DB는 URL을 먼저 확정하지 않으면 V16 적용이 실패한다.

## 검토한 대안과 기각 사유

| 대안 | 판단 |
|---|---|
| URL만 저장 | 외부 페이지가 수정·삭제되면 동의 당시 문구를 재현할 수 없다 |
| 전문만 저장 | 기능명세서 §1.6의 Notion 링크 열기 계약을 충족하지 못한다 |
| Notion 내용을 요청 때마다 동기화 | 외부 장애와 원본 변경이 API 응답 및 과거 증빙에 직접 영향을 준다 |
| 파일 저장소에 전문과 해시를 보관 | 현재 두 문서 규모에서 별도 저장·배포·복구 경로가 늘어난다 |

## 검증 계약

`TermsMigrationIT`에서 V16 fresh 적용과 V15 업그레이드, 두 종류·버전·URL·필수 여부·시행 시각, 전문 핵심 조항과 UTF-8 바이트 길이, HTTPS/필수값 제약, 앱 업데이트 URL 미등록 및 Flyway 재실행 멱등성을 검증한다.
