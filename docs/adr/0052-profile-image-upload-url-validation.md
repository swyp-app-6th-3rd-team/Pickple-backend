# ADR-0052: 프로필 사진은 기존 업로드와 URL 계약을 재사용하고 소유자·용도를 검증한다

- 상태: Accepted
- 날짜: 2026-09-14
- 관련: #173(F01)
- 보완: ADR-0019의 프로필 저장 책임과 ADR-0027의 이미지 공개 URL
- 참조: ADR-0040의 탈퇴 시 개인정보 파기
- 적용 범위: PROFILE 업로드 및 POST/PATCH /users/profile의 이미지 입력

## 맥락

develop 1210733의 업로드는 PRODUCT·COMMENT 두 용도만 지원한다.
프로필 API는 임의 URL을 저장하며 업로드 소유자와 용도를 확인하지 않는다.
사용자는 기존 코드를 최대한 재사용해 프로필 사진 등록·수정을 연결하도록 요청했다.

## 결정

- 기존 POST /images에 PROFILE을 추가한다. 한 장만 허용하고 기존 JPEG·PNG 시그니처,
  파일당 용량 검사, S3 저장과 실패 보상을 재사용한다.
- 기존 profileImageUrl 요청 및 응답 필드를 유지한다. 업로드 응답 images[0].accessUrl을 전달한다.
- 새 URL은 소유자와 URL로 item_container·item_resource를 조회해 PROFILE 한 장인지 검증한다.
  MySQL collation과 S3 키의 대소문자 처리 차이를 막기 위해 Java에서 URL을 정확히 비교한다.
- 기존 URL 재전송과 이미지 미전달은 기존 사진을 유지한다. 설정된 기본 이미지 URL은 명시적으로
  선택할 수 있다. 그 밖의 미등록·타인 소유·용도 불일치 URL은 INVALID_REQUEST(400)로 거부한다.
- 검증은 사용자 변경 전에 수행하며, 닉네임 충돌 처리와 트랜잭션은 기존 저장 경계를 재사용한다.
- V16은 컨테이너 CHECK의 허용 값을 확장하고 access_url 동등 검색용 인덱스를 추가한다.
  기존 데이터, 부착 측 복합 FK 및 과거 마이그레이션은 변경하지 않는다.
- F01은 자동 이미지 정리기나 스케줄러를 추가하지 않는다. 교체·탈퇴·미연결 PROFILE 객체는
  운영자가 활성 프로필 URL을 다시 확인한 뒤 S3 객체와 item_container를 직접 삭제한다.
  item_resource는 컨테이너 FK의 ON DELETE CASCADE로 함께 삭제한다. 자동 식별·재시도와
  CloudFront 캐시 무효화는 후속 FIX에서 다룬다.

## 결과와 트레이드오프

프론트는 기존 업로드 응답과 프로필 DTO로 연결할 수 있다. 새 임의 외부 URL 입력은 더 이상
허용되지 않으므로 호출자는 PROFILE 업로드를 먼저 수행해야 한다. 기존 저장 URL은 유지한다.
인덱스는 URL 조회의 전체 리소스 탐색을 피하기 위한 것이며 지연시간 개선을 측정한 주장은 아니다.

users는 URL을 보존하므로 컨테이너 FK는 새로 생기지 않는다. 자동화 전에는 업로드 직후 연결 중인
이미지나 다시 선택된 과거 이미지를 지우지 않도록 활성 URL과 정리 시점을 운영자가 확인해야 한다.
프로필 쓰기와 수동 삭제의 경쟁을 피할 수 없는 시점에는 프로필 변경을 잠시 중지한 상태에서 정리한다.
S3 삭제 실패 건은 item_key를 보존해 다시 처리하고, DB에서는 item_container를 삭제해
item_resource를 함께 정리한다. 탈퇴 이미지도 같은 절차로 지체 없이 처리한다. 후속 FIX는 이 판단과
재시도를 자동화하고, 1년 immutable 캐시가 탈퇴 후 객체를 계속 제공하지 않도록 PROFILE 캐시 정책
또는 CloudFront invalidation을 함께 결정한다.

배포는 V16 적용 후 PROFILE을 받는 코드를 사용한다. 롤백 시 PROFILE 데이터가 존재하는 동안
기존 CHECK로 축소하면 안 된다. 스키마 확장은 유지하고 PROFILE 요청을 중단한 뒤 이전 코드로
돌릴 수 있으나, 기존 코드는 PROFILE enum을 읽을 수 없어 관련 조회 경로를 함께 확인해야 한다.
F02 기본 이미지 파일·CDN 정상화와 실제 앱 표시는 별도 검증이다.

## 대안

- 새 컨테이너 ID 필드와 users FK: 무결성 경계는 강화되지만 기존 URL 데이터 변환과 프로필
  저장·탈퇴 처리 확장이 필요하다. 현재 흐름에는 기존 URL과 업로드 저장소 검증을 우선한다.
- PROFILE enum만 추가: 타인 이미지 연결과 다른 용도 재사용을 막지 못한다.
- 기존 임의 URL 허용 유지: 소유권 검증 요구를 충족하지 않는다.
- 전용 프로필 업로드 API: 저장·검증·실패 보상을 중복한다.
