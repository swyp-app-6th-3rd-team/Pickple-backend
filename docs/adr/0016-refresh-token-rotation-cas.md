# ADR-0016 — refresh token 회전은 CAS로 직렬화하고 현재 token을 보존한다

**상태**: Accepted

## 맥락

[ADR-0006](0006-auth-hardening.md)은 제출된 refresh token 해시가 저장된 해시와 다르면 현재 token을
폐기해 재로그인을 강제하도록 결정했다. 또한 회전 구현은 저장값을 조회하고 비교한 뒤 새 값을 쓰는
순서라서, 같은 token을 사용한 동시 요청이 모두 비교를 통과할 수 있었다.

이 경우 두 요청이 서로 다른 새 token을 반환하지만 마지막 저장값만 유효해진다. 늦게 도착한 요청이
옛 token을 다시 제출하면 현재 정상 token까지 삭제해 사용자를 재로그인시키는 문제가 생긴다.
사용자당 refresh token 한 행만 저장하는 현재 스키마로는 악의적 재사용과 정상적인 지연·재시도를
구분할 수도 없다.

## 결정

- refresh token 회전은 `user_id`와 제출된 `token_hash`를 조건으로 한 CAS `UPDATE`로 수행한다.
- 같은 token을 사용한 동시 요청 중 DB 갱신 행 수가 1인 한 요청만 성공한다.
- 저장 해시 불일치와 CAS 경합 패자는 401 `INVALID_TOKEN`으로 거부한다.
- 거부된 요청은 현재 저장된 승자 token을 삭제하지 않는다.
- 다중 기기나 token 재사용 계보를 구분해야 하면 별도의 token-family 스키마를 도입한다.

이 결정은 ADR-0006의 **리프레시 토큰 재사용 탐지** 문단과 결과 표의
`회전된 옛 토큰 재사용` 정책을 대체한다.

## 결과

- 동시 회전에서 하나의 새 token만 유효하다는 조건을 DB의 원자적 갱신으로 보장한다.
- 늦게 도착한 정상 요청이 다른 요청의 현재 token을 폐기하지 않는다.
- 단일 행 스키마를 유지하므로 마이그레이션은 필요하지 않다.
- 현재 구조에서는 실제 탈취 token 재사용을 정상 지연 요청과 구분하지 못한다. 탐지·세션별 폐기가
  필요해지면 token-family 도입 비용을 감수해야 한다.
- 단위 테스트는 CAS 성공·패자·해시 불일치를, 통합 테스트는 옛 token 거부 후 승자 token의 유효성을 검증한다.

## 검토한 대안

| 대안 | 기각 사유 |
|---|---|
| 해시 불일치 시 현재 token 삭제 유지 | 정상적인 동시 요청도 승자 token을 삭제해 불필요한 재로그인을 만든다 |
| 사용자 행 비관적 잠금 | 직렬화는 되지만 인증 요청이 사용자 행 잠금과 결합되고 잠금 대기 시간이 늘어난다 |
| token-family 즉시 도입 | 기기별 세션 정책이 확정되지 않은 상태에서 스키마·폐기 정책 복잡도가 커진다 |
| 애플리케이션 JVM 잠금 | 다중 인스턴스에서는 동일 사용자 요청을 직렬화하지 못한다 |
